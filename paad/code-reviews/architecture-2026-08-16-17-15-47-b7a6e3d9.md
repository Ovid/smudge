This branch lands five architecture-report fixes (F-09, F-11, F-13, F-20, F-27), each
with its own commit and Status block. The mechanical core of every fix verified sound
under adversarial checking — most notably the F-27 transaction, which three specialists

license audit. The fourth is a test-isolation defect the branch introduced. Confidence
is high: every finding was verified against live code, and 12 of 18 raw findings were

- **File:** `packages/client/src/__tests__/eslintImportCycleRule.test.ts:32-39` (fixture paths + `afterEach(cleanup)`); collides with `packages/client/src/__tests__/migrationStructuralCheck.test.ts:79-98`, `:131-141`

### Notable claims cleared under adversarial checking

Recorded because each was a plausible defect that verification refuted — they should not be re-litigated by a future review:

- **`store.transaction(async …)` is genuinely atomic.** `SqliteProjectStore.transaction` (`packages/server/src/stores/sqlite-project-store.ts:315-323`) delegates to **Knex**, not better-sqlite3's synchronous `db.transaction()`. Verified empirically against the installed knex 3.2.9 + better-sqlite3 with a real async gap: statements after an `await` land inside the transaction and a throw rolls back. Knex's sqlite dialect forces `pool {min:1,max:1}`, and all three calls use `txStore`, so there is no self-deadlock. **The F-27 fix is real.**
- **The F-13 `unmounted` flag is correctly placed.** The effect's dep array is `[]`, so cleanup fires only on real unmount; the flag is checked before both the state write and the `setTimeout`; StrictMode-safe. No timer leak, no stale-timer clear from rapid presses, and out-of-order resolution announcing a stale title is unreachable (a keydown is a macrotask).
- **The `CREATE TRIGGER` cannot leak across test *files*.** `setupTestDb` creates a `:memory:` DB per file in `beforeAll`; tests within a file are sequential. (The within-file gap is S4.)
- **Dropping `@tiptap/pm` from `packages/server` is production-install-safe.** `@tiptap/starter-kit` carries it as a hard dependency, and `packages/shared` declares the TipTap set as its own prod deps — a real contract, not hoisting.
- **Supply chain is clean.** The lockfile adds exactly 5 packages plus a nested `zod` copy and removes `@types/dompurify`, with zero silent version bumps. All licenses are ISC or MIT (on CLAUDE.md's acceptable list); `node scripts/dep-cooldown.mjs` passes with the allowlist still empty, so the exact `3.8.7` pin did its job.
- **F-20 did not weaken sanitization.** `packages/client/src/sanitizer.ts` is not in the diff; `ALLOWED_URI_REGEXP` and the `uponSanitizeAttribute` hook are byte-identical, and `tsc -b --force` passes with the stub removed.
- **F-27 does not contradict CLAUDE.md's accepted trade-offs.** F-3/F-2 were accepted on the single-writer premise for locator wiring and log correlation; F-27 is a match-the-siblings consistency fix its own caveat honestly labels as such.
- **The one-feature rule.** The Spec Compliance specialist raised the five-fix batch as a possible §Pull Request Scope violation; the Verifier dropped it. `main` carries five prior `Merge branch 'ovid/architecture'` merges (`a3067550`, `aae543eb`, `15df12cc`, `877b94e9`, `8b361146`), all identically shaped per-finding architecture batches. A settled, five-times-repeated workflow with no user-visible defect is a maintainer policy preference, not a review finding.
