### [I1] `discoverCallers()` drops any file that acquires its `useEditorMutation` handle in an unrecognised spelling, so the F-07 forcing pause still fails green in the one direction it exists to block
- **File:** `packages/client/src/__tests__/mutationCommittedSurface.test.ts:78-79` (`HANDLE_RE`), consumed at `:82`, acted on at `:145`, asserted at `:153`
- **Bug:** `HANDLE_RE` captures exactly two spellings — `(const|let|var) NAME = useEditorMutation(` and `NAME: ReturnType<typeof useEditorMutation> | UseEditorMutationReturn`. A file matching neither yields `extractMutationHandles() === []` and is skipped outright by `if (extractMutationHandles(source).length === 0) continue;` at `:145`. It contributes no key, so `expect(discoverCallers()).toEqual(COMMITTED_CALLERS)` at `:153` stays green. The second assertion cannot rescue it either: `it.each(Object.keys(COMMITTED_CALLERS))` at `:156` iterates the **hardcoded** list, not the discovered set. Three spellings were verified to produce `handles = []`: the one-step destructure `const { run } = useEditorMutation({...})` (the `\w+` cannot match `{`); a deps interface imported from a sibling module; and a `Pick<ReturnType<typeof useEditorMutation>, "run">` narrowing.
- **Why the imported-deps shape is concrete, not hypothetical:** `FindReplaceControllerDeps` (`packages/client/src/hooks/useFindReplaceController.ts:25`) and `SnapshotControllerDeps` (`packages/client/src/hooks/useSnapshotController.ts:63`) are exported interfaces that declare `mutation: ReturnType<typeof useEditorMutation>` **inline** — that inline declaration is the only reason either controller is discovered today. `packages/client/src/hooks/useProjectEditor.types.ts` is the established local precedent for hoisting a hook's deps types into a sibling `.types.ts`. Applying that precedent to either controller silently removes it from the committed surface.
- **Sibling divergence:** the neighbouring detector handles this case rather than skipping it. `packages/client/src/__tests__/migrationStructuralCheck.test.ts:171-183` gates on `importPatternFor(...)` **first** and treats "imports the hook but yields no binding" as an offender. The new file has no import gate, so zero-handle means invisible instead of loud — the weaker half of the pattern its own header cites as precedent at `:75-77`.
- **Two texts added by this branch are false as written:** `mutationCommittedSurface.test.ts:61-62` ("A file can obtain a useEditorMutation handle exactly two ways, and TypeScript forces the hook's own name to be spelled out in both" — TypeScript forces no such thing), and `paad/architecture-reviews/2026-08-11-smudge-architecture-report.md:307` ("**The claim above now holds as written**", where the claim at `:306` is "A third caller landing without a handler turns the surface assertion red"). The header at `:54-55` is true only for the two-step `const { run } = mutation` destructure it names.
- **Impact:** `useEditorMutation.ts`'s `finally` dispatches nothing on the `reloadFailed` path (`// no-op: consumer owns COMMITTED_UNRELOADED`), so an unguarded caller leaves the machine at `editable:false` with no lock banner — a read-only editor with nothing on screen explaining it, recoverable only by refresh. That is the F-07 defect itself; this guard is the only thing standing between a future refactor and shipping it.
- **Suggested fix:** widen discovery to the import edge — `importPatternFor` is already exported at `migrationStructuralCheck.test.ts:58`, and was the prior code review's own suggested approach — making "imports the hook but binds no handle" an offender rather than a `continue`. If the import gate is rejected, correct `:54-55`, `:61-62`, and report line `307` to enumerate the real ceiling instead of asserting there is one remaining shape.
- **Confidence:** High

### [I2] A `run()` call **added** to an already-listed file in a shape `countMutationRuns` cannot see passes both assertions green
- **File:** `packages/client/src/__tests__/mutationCommittedSurface.test.ts:106`, consumed at `:146`, asserted at `:153` and `:160`
- **Bug:** the per-handle pattern is ``new RegExp(`\\b${name}\\s*\\??\\.\\s*run\\s*(?:<[^>]*>)?\\s*\\(`)``. Three shapes contribute 0: a receiver that is not the bound handle name (`const { run } = deps.mutation; run(...)`), a different receiver expression (`ref.current.run(...)`), and a nested generic (`run<Array<string>>(` — `<[^>]*>` stops at the inner `>` and then demands `\s*\(`). The file's run count is therefore unchanged, so the surface assertion at `:153` still matches `COMMITTED_CALLERS`; the added call carries no `committed_but_unreloaded` branch, so the pairing at `:160` also compares two unchanged numbers. Both green. Reproduced against the real `useFindReplaceController.ts` source with one appended unguarded call, using the shipped helper bodies verbatim.
- **Three places in the tree assert the opposite:** the header at `:52-55`, the docstring at `:96-100` ("the file then reports fewer runs than the committed surface records, which is a false RED"), and the self-test at `:250-257`, whose fixture is a bare file where the destructure is the **only** call. The claim holds when an uncounted shape *replaces* a counted call; it is false when one is *added* — which is exactly the "third caller lands" scenario the guard exists for.
- **Impact:** same as [I1] — an unguarded `committed_but_unreloaded` caller ships, stranding the editor read-only with no banner. This is a *second, independent* hole in the same file, closed by a different fix.
- **Suggested fix:** once `extractMutationHandles(source).length > 0`, count receiver-blind within that file — every `/\.\s*run\s*(?:<.*?>)?\s*\(/g` plus bare `run(`. Over-counting inside a handle-holding file fails in the safe direction (false red). Extend the `:250-257` self-test to the additive case, which currently passes and should not.
- **Confidence:** High
- **Found by:** Error Handling & Edge Cases (`claude-opus-5[1m]`)
