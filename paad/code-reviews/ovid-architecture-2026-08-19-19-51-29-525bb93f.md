## Important Issues

### [I1] Cross-project unmount flush posts the stale ref instead of the caller's content, losing the last keystrokes
- **File:** `packages/client/src/hooks/useProjectEditor.ts:331-333` (the new gate), interacting with `:397-398`, `:279`, `:653-657`, `:431-434`
- **Bug:** Commit `525bb93f` stopped seeding `latestContentRef` for a save whose chapter is not the active one, but left the read at `:397-398` — `const postedContent = latest && latest.id === savingChapterId ? latest.content : content;` — which still *prefers* the ref over the caller's `content` argument whenever the ids match. Nothing on the project-switch path clears the ref, so it still holds the old chapter's older content. The window that makes this reachable: `loadProject` writes `activeChapterRef.current = null` **directly** at `:279`, inside an async continuation, and then awaits the chapters GET. The old chapter's `Editor` stays mounted and typable until React commits that render. A keystroke landing in that gap updates neither the ref nor the draft cache, because `handleContentChange` (`:653`) is gated on `if (activeChapterRef.current)`. The subsequent unmount cleanup then calls `handleSave(getJSON(), A)` with the fresh content, the gate skips the seed, `:398` posts the ref's *stale* content instead, the PATCH succeeds, and `clearCachedContent(A)` deletes the draft. The last keystrokes exist nowhere.
- **Impact:** Silent loss of the user's most recent typing plus deletion of the localStorage draft entry — the mechanism CLAUDE.md save-pipeline invariant 3 names as "the last line of defense against data loss." This is a regression: the identical interleaving was lossless before this commit, because the unconditional seed made `ref.content === content` by construction. Reachability is low (needs a cross-project navigation started while the chapter is dirty, plus a keystroke inside a single event-loop turn), but the invariant the code now rests on — "a save for chapter X always posts content at least as new as `cache(X)`" — is simply false on this path.
- **Suggested fix:** Capture whether the seed ran and let only a seeded save read the ref:
  ```ts
  const seeded = savingChapterId === activeChapterRef.current?.id;
  if (seeded) latestContentRef.current = { id: savingChapterId, content };
  // …
  const latest = seeded ? latestContentRef.current : null;
  const postedContent = latest && latest.id === savingChapterId ? latest.content : content;
  ```
  This keeps the commit's intent (the ref never carries a foreign id) while restoring "a non-active save posts exactly what its caller handed it" — which is also the property that makes the later `clearCachedContent(savingChapterId)` safe. Worth closing in the same edit: `handleContentChange` writing *nothing* when `activeChapterRef.current` is null also drops the keystroke from the draft cache. That hole pre-dates this branch (`:653` is untouched) and was masked by the unconditional seed; after the fix above the keystroke is posted, but if that PATCH fails there is still no cached copy.
- **Confidence:** Medium
- **Found by:** Concurrency & State (`claude-opus-5[1m]`), corroborated by Contract & Integration (`claude-opus-5[1m]`), confirmed by the Verifier against the code

### [I2] `stripCommentsFromTsSource` deletes executable code for two regex/template positions; the recorded ceiling is wrong in the same load-bearing half a second time
- **File:** `packages/client/src/__tests__/tsSourceScan.ts:47-52` (pattern at `:49`; ceiling claim at `:29-44`)
- **Bug:** The regex-literal lookbehind class `[=(,:[!&|?{};]` contains no `>` and admits no keyword, so `=> /…/` and `return /…/` — two of the most common regex positions in TypeScript — never enter the regex branch. They fall through to the string/line-comment alternatives instead, and the string alternative has no newline exclusion, so a fake literal runs to the next quote anywhere below. Separately, the backtick alternative cannot span a `${…}` holding a nested template. All three were reproduced by execution against the shipped pattern:
  - `const isAbsolute = (s) => /^https?:\/\//.test(s) && mutation.run(f);` strips to `const isAbsolute = (s) => /^https?:\/`, deleting the `mutation.run(f)` call.
  - `return /"/.test(s);` above `glob("**/*.ts")` erases everything down to the next real `*/`, taking out a `const mutation = useEditorMutation({})` binding *and* an `await mutation.run(doReplace)`.
  - `` const css = `${rules.map((r) => `//${r}`).join("")}`; await mutation.run(f); `` strips to `` const css = `${rules.map((r) => ` ``.
  - Control: `const re = /"/;` (the position round 3's S3 fixture uses) strips correctly — which is exactly why the round-3 fix looks complete.
- **Impact:** Counts go **down**, which is the silent-green direction. A new `useEditorMutation` caller that receives its handle through a hoisted deps interface — no local binding, no direct import — sitting inside an erased span yields `handles: []`, `runs: 0`, `importsHook: false`, so `discoverCallers()` skips it at `mutationCommittedSurface.test.ts:295`, `toEqual` compares unchanged objects, and the F-07 forcing pause ships green on an unguarded caller. The comment at `:41-43` narrows the residual to "a real comment INSIDE a mis-detected span survives, a false RED", so a reader cannot learn from it that legal regex positions are *missing from the class*. **Latent, not live:** two independent differential checks against the TypeScript 5.9 parser's own comment ranges over every non-test source under `packages/client/src` found zero divergence. Nothing is miscounted today.
- **Suggested fix:** `typescript@5.9.3` is already a root devDependency and both consumers are Node-side test files. Replace the body with a `ts.createScanner(ts.ScriptTarget.Latest, /*skipTrivia*/ false, variant, source)` loop that drops `SingleLineCommentTrivia` / `MultiLineCommentTrivia` and concatenates every other token verbatim. The self-tests at `migrationStructuralCheck.test.ts:375-457` pin the contract and should pass unmodified; the three ceiling paragraphs at `:12-46` then delete, including the disclosed JSX residual. This is one edit closing all three holes — a fourth hand-patch to the same regex would be the fourth consecutive round. If the tokenizer is declined, the minimal patch is `(?<=(?:[=(,:[!&|?{};>]|\b(?:return|typeof|case|yield|await|in|of|do|else))\s*)` plus a `${…}`-spanning template alternative, and `:39-44` must then be corrected to name the true residual.

### [I3] Caller discovery misses a `Pick<>`-narrowed handle, the fourth silent-green shape in F-07's forcing pause
- **File:** `packages/client/src/__tests__/mutationCommittedSurface.test.ts:110-111` (`HANDLE_RE`) and `:294-299`
- **Bug:** `HANDLE_RE`'s second alternative requires the type name *immediately* after the colon, so a handle declared as `Pick<UseEditorMutationReturn, "run">` binds nothing. Reproduced by execution against the shipped helpers:
