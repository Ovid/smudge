## Executive Summary

The branch's core change is sound: `useEditorMutation` now settles the
committed-but-unreloaded transition itself, and making `MutationDirective.committedLock`
required genuinely converts a comment-borne caller obligation into a compile error.
`tsc --noEmit` is clean and all 1,899 client tests pass. No Critical issues.

The highest-severity finding is that the seam's new `drifted` verdict ignores
`directive.clearCacheFor`, so it re-enables the editor on exactly the chapter whose
failed reload was the reason to lock — silently neutralizing two escalation sites in
the same file whose comments state the opposite intent. Three independent specialists
found it. The second theme is documentation: `CLAUDE.md` and five in-tree comment blocks
still describe the pre-fix contract, and one of them would lead a future consumer into
reconstructing the exact defect F-07 closed. Confidence in the findings is good — the
verifier reframed or rejected four specialist claims on the code rather than accepting
them.

## Important Issues

### [I1] `drifted` ignores `clearCacheFor`, re-enabling the editor on the chapter whose reload just failed
- **File:** `packages/client/src/hooks/useEditorMutation.ts:181-189` (verdict), acted on `:562-573`; neutralized escalation sites `:388-391`, `:502-503`, `:529-532`
- **Bug:** `committed()` computes `drifted` from `committedLock.targetChapterId` and the live
  active chapter only. It never consults `d.clearCacheFor`, which it holds. But both
  escalation sites *require* the active chapter to be in `clearCacheFor` to reach
  `committed()` at all — `:389` reads
  `if (currentId && directive.clearCacheFor.includes(currentId)) return committed(directive);`
  and their comments state the intent verbatim: "Escalate to `committed_but_unreloaded`
  so callers raise the persistent lock banner instead" and "the very next keystroke would
  PATCH stale content back over the server-committed change". Whenever the drifted-onto
  chapter is itself an affected chapter, `drifted` is `true`, the `finally` dispatches
  `MUTATION_SETTLED_SUPERSEDED` → `{editable:true, lock:null}`, and both escalations are
  silently neutralized.
- **Impact:** Project-scope Replace All on chapter A affecting A and B; user switches to B
  mid-flight; the confirming GET for B fails. B's draft cache was already wiped at
  `:397-399`, and B's post-replace content was never fetched — so the user is handed a
  writable editor showing B's pre-replace document. `handleSaveLockGated` gates only on
  `lock !== null`, so with `lock:null` the 1.5s auto-save PATCH is unblocked and reverts
  the server-committed replace, with no cached draft left to recover from. The new
  safety-net test pins this as correct:
  `committedUnreloadedEndState.test.tsx:189-205` uses
  `affected_chapter_ids: [TARGET, DRIFTED]` and asserts `{editable:true, lock:null}`,
  its own comment conceding "The user is on a chapter the replace targeted but did not
  START on."
- **Scope note:** the *end state* matches `main` — `main`'s `finalizeReplaceSuccess`
  computed the same verdict and produced the same re-enable. It is in-scope anyway: the
  anchor is newly-authored code (so cosmetic-touch demotion cannot apply), and the branch
  expanded the blast radius by moving the rule into the one place that also holds
  `clearCacheFor` and `reloadChapterId`, using neither, and making that verdict
  authoritative for every future consumer by construction.
- **Suggested fix:** in `committed()`, add
  `const affected = currentId !== undefined && d.clearCacheFor.includes(currentId);` and
  `&& !affected` to the `drifted` conjunction. Then change
  `committedUnreloadedEndState.test.tsx:189-205` to `affected_chapter_ids: [TARGET]` to
  keep expressing OOSI1, and add a sibling with `[TARGET, DRIFTED]` asserting the lock.
  The distinction between those two arrays is the whole content of this finding.
- **Confidence:** Medium
- **Found by:** Logic & Correctness (`claude-opus-5[1m]`), Error Handling & Edge Cases (`claude-opus-5[1m]`), Contract & Integration (`claude-opus-5[1m]`)
