### [I1] Outtake capture lands in the wrong project when the user navigates mid-POST
- **File:** `packages/client/src/pages/EditorPage.tsx:1009` and `:1012`; mishandling half at `packages/client/src/components/OuttakesPanel.tsx:139-144` (via `applyServerRow`, `:118-125`)
- **Bug:** `handleSendSelectionToOuttakes` (977-1016) captures `project` at entry and gates its post-await writes on `signal.aborted` alone. `captureOp` is a `useAbortableAsyncOperation` — aborted only by unmount or a newer `run()`, neither of which fires on `/projects/:slug` navigation (`App.tsx:23` is unkeyed). `EditorMainContent.tsx:406` renders `<OuttakesPanel>` with no `key`, outside the view-mode branch, so it survives preview/dashboard/trash *and* project switches. The panel's prepend effect checks only `surfacedCaptureIdRef.current === capturedOuttake.id` (seeded at first render), and `applyServerRow` has no `project_id` compare at any of its three call sites. `reconcile()` → `seq.abort()` additionally stales project B's in-flight list load; when no load is in flight it issues no refetch, so the phantom row persists for the session.
- **Impact:** Project A's outtake card renders in project B's list. Its "Insert into editor" pastes A's private stashed text into a B chapter; its Delete **hard-deletes** a real project-A outtake (outtakes have no `deleted_at` — CLAUDE.md §Data Model) that the user believes is stray. On the failure path, A's `createOuttakeFailed` banner paints over B and nothing clears `actionError` on project change. This is the class `staleProjectGuard.ts:5-12` was written for: "Every post-await state write and every user-visible banner in a project-scoped async handler needs this."
- **Suggested fix:** Two loci, both wanted. (a) Root cause — `if (row.project_id !== projectId) return;` at the top of `applyServerRow` (`OuttakesPanel.tsx:119`), which closes the mount path, the prop-change path, **and** `handleCreate`'s blank-note path in one place. (b) Banner leak — a drift guard at the `EditorPage` site before `setActionError`/`setCapturedOuttake`; note `EditorPage` has no `projectRef`/`projectSlugRef` in scope, so `makeStaleProjectGuard` there needs a ref surfaced from `useProjectEditor` first. A `key={project.id}` on `<OuttakesPanel>` would close (a) plus [I2] and [I3] in a single line.
- **Confidence:** Medium (78)
- **Found by:** Logic & Correctness, Error Handling, Contract & Integration, Concurrency & State, Security, Spec Compliance — all 6 partition-B lenses (`general-purpose (claude-opus-5[1m])`)

### [I2] A successful blank-note create wipes a newer draft the writer typed after cancelling
- **File:** `packages/client/src/components/OuttakesPanel.tsx:160-161`
- **Bug:** `handleCreate`'s post-await tail runs `setDraft(""); setShowNew(false);` unconditionally. The Cancel button (`:248-253`) carries no `disabled={creating}` — only Save does. So: type "scene A" → Save → Cancel (form hides, draft cleared) → "New outtake" → type "scene B" → the first POST resolves → "scene B" is erased and the form closes under the writer.
- **Impact:** Silent loss of typed-but-unsaved text, with no banner and no undo. The file's own sibling `OuttakeCard.commitLabel` guards exactly this with a `current === attempted` compare, and the panel's S3 comment (`:171-173`) calls discarding the writer's text "the one failure this panel exists to prevent" — so the create path is the one place in the component that violates its own stated contract.
- **Suggested fix:** Snapshot `const attempted = draft;` before `createOp.run`, then `setDraft((current) => (current === attempted ? "" : current));` and gate `setShowNew(false)` on the same predicate.
- **Confidence:** Medium (68)
- **Found by:** Concurrency & State (`general-purpose (claude-opus-5[1m])`)

### Out-of-Scope Important

#### [OOSI1] `$`-sequences in an image caption splice the document into the export — backlog id: `1079f80c`
- **File:** `packages/server/src/export/image-resolver.ts:161-163`
- **Bug:** The figure/figcaption pass uses a **string** replacement whose replacement text interpolates `escapeHtml(fullCaption)`. `escapeHtml` (`export/html-escape.ts`) escapes only `& < > " '` — it does not neutralise `$`, and `$$`, `` $` ``, `$'`, `$&` are all special in a `String.replace` replacement string. `escapeHtml` also *manufactures* the hazard: it rewrites `'` → `&#39;` and `&` → `&amp;`, so a caption containing `$'` or `$&` becomes `$&…`, the match-substitution token.
- **Impact:** `fullCaption` comes from the user-editable `caption`/`source`/`license` columns set via `PATCH /api/images/:id`. `` $` `` injects the entire preceding portion of the rendered HTML into the figcaption; with a base64-embedded image that duplicates the whole document body once per captioned image, silently and with no warning to the writer. Affects HTML, Markdown, plaintext and EPUB (all four route through `resolveImageSrcs`); DOCX is unaffected. **This is the highest-severity item in the review.**
- **Suggested fix:** `resolvedHtml.replace(re, (_m, tag: string) => \`<figure>${tag}<figcaption>${escapeHtml(fullCaption)}</figcaption></figure>\`)` — the same function-replacer shape the branch's own C1 change applied eight lines above.
- **Confidence:** High (80)
- **Found by:** Error Handling & Edge Cases (`general-purpose (claude-opus-5[1m])`)
- **Backlog status:** new
- **Classification note:** The anchor lines are not in the touched-lines map — this hunk is unchanged from `main`. The adjacent C1 rewrite at `:152` did convert the *sibling* substitution to a function replacer, but its stated reasoning is regex duplication, not replacement-string escaping, so reasoning-promotion does not honestly apply.
