#### [C1] "Is this src an `/api/images/<uuid>` reference?" encoded 5×; two encodings run in sequence on the export path and disagree about a `?query` suffix, silently deleting the `<img>`

- **Canonical concept:** Recognise a Smudge image reference in content or rendered HTML.
- **Duplicate locations:**
  - `packages/client/src/sanitizer.ts:110` — `ALLOWED_URI_REGEXP`, accepts `(?:[?#].*)?$`
  - `packages/server/src/export/export.renderers.ts:63` — `ALLOWED_IMAGE_SRC`, accepts `(?:[?#].*)?$` (used by `stripDisallowedImages:65` and by the DOCX walker at `docx.renderer.ts:338`)
  - `packages/server/src/images/images.references.ts:37` — `IMAGE_SRC_RE`, accepts `(?:[/?#]|$)` (refcounting)
  - `packages/server/src/images/images.paths.ts:15` — `IMAGE_SRC_REGEX` = `src="/api/images/(UUID)"`, **closing quote mandatory ⇒ rejects any suffix**
  - `packages/server/src/export/image-resolver.ts:139` — a fifth, inline `new RegExp(\`src="/api/images/${id}"\`, "gi")`, same suffix-hostile shape
- **Why these are semantically duplicate:** All five answer the same question about the same URL space; four are near-copies of one pattern spliced from the same `UUID_PATTERN`.
- **Verified mechanism** (empirically simulated in `node`): for `src="/api/images/<uuid>?v=2"` — `stripDisallowedImages` **keeps** the tag (its allowlist accepts the suffix); `resolveImageSrcs` (`image-resolver.ts:124-160`) scans with `IMAGE_SRC_REGEX` and extracts **no id**; the catch-all at `image-resolver.ts:158` (`/<img[^>]*src="\/api\/images\/[^"]*"[^>]*>/gi`) then **deletes the whole `<img>`**. Bare src → image embedded. Suffixed src → `""`. Same for `#frag`.
- **Reachability — verified, and stronger than the reporting specialist conceded:** `@tiptap/extension-image` parses `img[src]:not([src^="data:"])` (`node_modules/@tiptap/extension-image/dist/index.js:40-47`) and preserves `src` verbatim; there is no paste sanitization on the input path (`Editor.tsx:88` `handlePaste` intercepts only clipboard *image files*); `TipTapDocSchema` is `.passthrough()` and never validates `attrs.src`. So pasting HTML containing a suffixed Smudge image URL stores it. Every other surface then agrees the image is present and in use — the client sanitizer renders it, and `IMAGE_SRC_RE` counts the reference so `deleteImage` **blocks** with `IMAGE_IN_USE`. Only the export drops it. No shipped writer emits a suffix today, so probability is low — but nothing prevents it, and adding a cache-buster query would make it universal.
- **Important differences:** The three security/refcount encodings must **not** be unified — CLAUDE.md F-16 keeps `ALLOWED_URI_REGEXP` and `IMAGE_SRC_RE` apart on threat-model grounds and that reasoning stands. This is not an F-16 finding.
- **Impact:** An image the writer can see in the editor and the preview, that the app refuses to delete because it is "in use", vanishes from the HTML / EPUB / markdown / plaintext export with no warning and no log line.
- **Suggested consolidation:** Make the *resolver* agree with the export allowlist it sits downstream of — widen `IMAGE_SRC_REGEX` to `src="/api/images/(UUID)(?:[?#][^"]*)?"` **and** the inline replace at `image-resolver.ts:139` the same way (both, or the id is found and the substitution still misses ⇒ still deleted). Then add `IMAGE_SRC_REGEX` as a third column to `packages/shared/src/__tests__/image-src-allowlist-parity.test.ts`, which today asserts `["a query suffix", …, true]` / `["a fragment suffix", …, true]` for two encodings and **omits the third entirely**.
- **Confidence:** High (90 — mechanism 98, paste reachability ~80)
- **Found by:** Divergence Risk (primary), Type & Constraint (independent corroboration)
- **Relationship:** overlapping, with realized drift
